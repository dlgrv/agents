# dlgrv browser-desktop site

Load this skill before editing anything in `/Users/dlgrv/github/dlgrv.com` — the user's
personal "залипательный мир" (explorable desktop world): macOS-style shell, Win95

## Stack & structure

Vite + TypeScript strict, **no framework**, FSD layers `app → pages → widgets → features → entities → shared`, alias `@/* → src/*`. Dev port **4923** (`--strictPort`).

Key files:
- `src/entities/profile/model/profile.ts` — desktop apps list (`AppInfo`: id/name/color?/glyph?/icon?/theme?/`side?`). `theme: 'win95'` gives an app a Win95 window (About is Win95; everything else macOS). `side: 'right'` puts the icon in a separate right-center column (see below). Current ids: `about`, `safari`, `lang` (left) + `photos`, `folder` (Blog), `wishlist` (right column, apple-folder pink "saves" icon). Window sizes per app-id live in `openWindow` opts in `window-manager/index.ts` (`safari` 720×420, `lang` 320×260, `about` 620×620, `wishlist` 640×420) — keep them proportionate to each other (user flagged a too-small wishlist window).
- `src/pages/desktop/ui/Desktop.ts` — builds TWO icon containers: `.desktop__icons` (default, top-left) and `.desktop__icons.desktop__icons--right` (right edge, vertically centered). Apps with `side: 'right'` go to the right column.
- `src/app/app.css` — `.desktop__icons--right { top:50%; right:40px; transform:translateY(-50%); flex-direction:column; align-items:flex-end; z-index:3 }`. The `z-index:3` is MANDATORY (see Pitfalls: icons-under-wallpaper-filter).
- `public/icons/` — source PNGs 128×128; `make-icon.py` generates PNG icons (squircle + glyph) in this folder. See `references/desktop-icons-layout.md`.
- `src/widgets/window-manager/index.ts` — `openWindow`, `restoreWindows` (localStorage persistence), `refreshWindow` (skips `lang`). **FSD: `widgets` must NOT import `features`.** These functions take a `WindowManagerDeps` arg (`renderContent`, `control`) injected from `app/index.ts`; a module-level `activeDeps` also holds them so `Desktop.ts` can call `openWindow(app)` on icon-click without threading deps through `pages`. **`restoreWindows(deps)` opens a default 3-window layout when localStorage is empty** (first visit AND after Reset): `openDefaultLayout(deps)`. `DEFAULT_LAYOUT` order is `[lang, about, safari]` — **Safari is opened LAST and gets `z: 11` + `.is-focused`** (others get `z: 10`), so the dino window is the active/focused default and **Space starts the game immediately without a click** (explicit user requirement). ## Pitfalls (each cost a debugging session)

- **`persist()` must NOT guard on `offsetParent`/DOM-connection.** In `Window.ts`, `persist()` runs INSIDE `createWindow`, i.e. BEFORE `layer.appendChild`. The old code did `if (!win.isConnected || !win.offsetParent) return;` → early-returned every time → default/auto-opened windows were NEVER saved to `localStorage`. Symptom: Reset → drag one window → reload → only the dragged window survived (its `persist` ran after append; the others' saves had silently failed earlier). Fix: make `persist` a pure read of `win.style.left/top` (already set at construction) into `computeWindowState` (`ui/state.ts`) with NO DOM guard. Regression test: `src/widgets/window-manager/__tests__/restore.spec.ts`.
- **FSD: `widgets` must never import `features`.** This repo is FSD; a layer may only import to its right. We found `window-manager` importing `renderWindowContent`/`onLanguageChange` from `features/open-window/content` and `controlWindow` from `features/window-controls`. Fix: introduce `WindowManagerDeps { renderContent; control }` injected from `app/index.ts` (which is allowed to compose `features` + `widgets`); `window-manager` keeps a module-level `activeDeps`. For language updates use `onLangChange` from `@/entities/lang/model/lang` (entities — allowed), NOT the `onLanguageChange` wrapper in `features`. Guard with `src/__tests__/fsd-layers.spec.ts` (fails if `widgets→features` or `shared/entities` import upward). Re-run that spec after any refactor. See `references/fsd-audit-vitest.md`.
- **e2e specs must target LIVE app ids.** After `telega/projects/links` were removed from `profile.ts`, any spec using `.app-icon:hasText('telega')` fails (icon no longer exists) — a false regression, not a real bug. ## Cross-row line-through styling

**Never use `text-decoration: line-through` alone for purchased state** — it only applies to text and leaves gaps between Name/Kind/Date columns. Instead, use a pseudo-element that spans the entire row:

```css
.wishlist-list__row.is-bought {
  color: #98989d;
}
.wishlist-list__row.is-bought .wishlist-list__icon {
  filter: grayscale(100%) opacity(0.6);
}
.wishlist-list__row.is-bought .wishlist-list__text {
  position: relative;
}
.wishlist-list__row.is-bought .wishlist-list__text::after {
  content: "";
  position: absolute;
  top: 50%;
  left: 0;
  right: 0;
  height: 1px;
  background-color: #98989d;
  transform: translateY(-50%);
}
```

**Key insight:** The line-through spans the entire text container (name + kind + date), including gaps between columns. The icon is outside this container and thus not crossed out, which matches Finder's behavior. **Do not duplicate with `text-decoration`** — the pseudo-element covers the text and the gaps.
