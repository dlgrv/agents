# Отчёт по практике (ГОСТ) — процедура и оформление

Набор документов: Титульный лист, Дневник практики, Аттестационный лист, Основная часть.

## Порядок работы

1. Собрать референсы: примеры одногруппников (титульник/дневник/аттестационный/основная часть) и ГОСТ-методичку из `~/university`. Сначала прочитать все эталоны, потом писать генератор.
2. Бланки (титул, дневник, аттестационный) заполнять поверх бланков-образцов через python-docx. Индексы ячеек таблиц сверять по фактическому бланку (`docx_read.py --text`), не по памяти — нумерация ячеек в бланках съезжает от ожидаемой.
3. Основную часть генерировать скриптом python-docx (`docx_create.py` или инлайн). Рисунки-схемы готовить заранее PNG (matplotlib/graphviz), проверить глазами через vision_analyze до вставки.
4. Результат класть в `~/university/<Тип работы> (<Фамилия И.>)/`; если по ходу работал в другой папке — синхронизировать копию в конце.

## Требования оформления (основная часть)

- Times New Roman 14, полуторный интервал, по ширине, абзацный отступ 1,25 см. Поля: левое 30 мм, верх/низ 20 мм, правое 15 мм по бланку (методичка может требовать 10 мм — сверять с ГОСТ-файлом, приоритет у методички).
- Заголовки (ГОСТ 7.32-2017, п. 6.2): нумерованные разделы («1 Характеристика предприятия…») — только первое слово с прописной, по левому краю, с абзацного отступа 1,25 см, полужирным; структурные (СОДЕРЖАНИЕ, ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ, СПИСОК…) — КАПС, по центру. Каждый раздел с новой страницы. Название темы на первом листе — по центру, без номера страницы на нём.
- Рисунки: по центру, подпись СНИЗУ по центру «Рисунок N.М — Название», без точки на конце. Названия таблиц: СВЕРХУ слева, без абзацного отступа, «Таблица N.М — Название», без точки. Нумерация в пределах раздела (1.1, 3.1).
- Номера страниц: поле PAGE внизу по центру, TNR 12 (`docx_edit.py page-numbers`).
- Перечень использованных источников по ГОСТ Р 7.0.100-2018: книга — «Город : Издательство, год. – N с. – Текст : непосредственный.»; сайт/док — «– URL: https://… (дата обращения: ДД.ММ.ГГГГ). – Текст : электронный.».
- Внутритекстовые ссылки [N] обязательны (ГОСТ Р 7.0.5-2008): проставлять при первом упоминании каждого источника; в конце проверить, что каждая позиция списка процитирована в тексте.
- Оглавление: в эталонах одногруппников содержания нет — не добавлять без запроса. Если пользователь просит содержание — строить СТАТИЧЕСКОЕ (обычные абзацы «Заголовок……N», точечная выравнивающая строка, номер через таб), не TOC-поле: Word через AppleScript поле не пересчитывает и не сохраняет в XML, страница разрастается от пустого поля. См. «Содержание (по запросу)» ниже.

## Содержание (по запросу)

1. Карта страниц: `/opt/homebrew/bin/soffice --headless --convert-to pdf` (LibreOffice, ставится `brew install --cask libreoffice`), затем pypdf: нормализовать текст страниц (убрать пробелы) и искать каждый Heading-текст, начиная со стр. 3 (содержание само занимает стр. 1–2 и содержит те же строки). Пропуск заголовка из-за фильтра страниц — типичная ошибка (ВВЕДЕНИЕ «не находилось»). Если заголовок перенёсся на две строки — искать по первым 20 нормализованным символам.
2. Вписать номера в статические строки содержания, СОХРАНИТЬ, снова отрендерить в PDF и сверить: число строк содержания = число заголовков, каждая строка = реальная страница (полная проверка, не выборочно).
3. После последней строки содержания — явный разрыв страницы (run с `w:br type=page` в последней строке содержания), чтобы первый раздел начинался с чистого листа; пустую страницу-разделитель перед содержанием при этом убрать.
4. При вставке/удалении текста после построения содержания — всегда пересчитывать карту и обновлять все строки заново (номера съезжают почти гарантированно).

## Питфоллы генерации

- Скрипт с правками писать в scratch через write_file и запускать файлом, `d.save()` — последняя строка, импорты — в начале. В инлайн-скрипте ошибка после правок, но до `save()`, молча теряет ВСЕ замены (типичный случай: пропущенный `Pt` в импорте падает на футере после успешных replace).
- Если CLI `docx_edit.py replace` долго не отвечает на тяжёлом файле (много картинок) — не ждать таймаута, сразу инлайн python-docx: заменить склейкой runs (полный текст параграфа в первый run, остальные очистить).
- После вставки/удаления рисунков и разделов перенумеровать «Рисунок N.М»/«Таблица N.М» заново — индексы почти гарантированно съезжают.
- Проверку ссылок [N] по извлечённому тексту делать с оглядкой на листинги кода: `capture_output=True` даёт ложное срабатывание на `[0]`; и наоборот — регекс одной цифры (`\[\d`) пропускает групповые ссылки «[1, 2]» — парсить ВСЕ скобочные группы `\[([\d,\s]+)\]` с разбиением по запятой и сверять множество с длиной списка источников.
- Декапс заголовков делай пословно: прописная только на первом слове, аббревиатуры (VLAN, IPTV, Python, TR-069) сохранять словарём-исключений; `str.capitalize()` на всей строке поднимает КАЖДОЕ слово («… Предприятия И Архитектура») — не использовать. После переименования заголовков синхронизировать строки статического содержания (они несут копии текстов) и пересчитать пагинацию; искать заголовки по старому КАПС-тексту после декапса нельзя — сначала вывести фактические тексты или искать регистронезависимо.
- Удаляя пустые абзацы перед заголовком в цикле — перечитывать `d.paragraphs` на каждой итерации: после удаления элемента индексы съезжают.
- Все элементы документа, включая листинги кода, — Times New Roman: стили кода несут Courier New по умолчанию. Проверять `w:rFonts` по всем run'ам (тело, таблицы, футеры) И в docDefaults/styles — отклонения живут не только в run'ах. Кегль листингов можно сохранять меньший.
- Слушай пользователя про объем: «распиши всё» = расширять разделы фактологией (история компании в регионе, даты, технологии) с поиском в интернете, сохраняя структуру разделов эталона.

## Финальный аудит (прогонять перед сдачей, одним скриптом)
1. Рендер LibreOffice → PDF: общее число страниц; пустых нет (`extract_text()` каждой страницы ≥ порога); все строки содержания = реальные страницы заголовков.
2. Все run'ы: шрифт TNR, цвет чёрный, без подчёркиваний/лишнего курсива; подписи «Рисунок N.М — Название» снизу и «Таблица N.М — Название» сверху, без точки на конце; на каждый рисунок/таблицу есть ссылка в тексте; каждый источник списка процитирован.
3. Поле PAGE в футере, поля страницы по бланку, латинские аббревиатуры без кириллических двойников. В конце — синхронизировать копию во второй папке, если работал в двух.
- Стилям Heading 1/2/3 Word по умолчанию даёт синий цвет темы — при назначении заголовков явно ставить чёрный (`font.color.rgb = RGBColor(0,0,0)`) на стиль И на run'ы, и удалять `themeColor` из rPr стиля. После правок контроль: пройтись по всем run'ам (включая таблицы), не-чёрных быть не должно.
- Латинские аббревиатуры (FTTB, GPON и т.п.) проверять на кириллические двойники букв (Б вместо B) — искать по кодам символов, а не глазами.
- Вставляя абзац «после заголовка, найденного по тексту», искать именно стиль Heading И вне диапазона содержания: строка содержания несёт тот же текст, и addnext улетает ВНУТРЬ оглавления. Симптом: посторонние абзацы между строками содержания, заголовки «дублируются».
- Разбивка страниц Word и рендера LibreOffice расходится: «пустая страница» бывает только в Word — большим таблицам не хватает места и Word переносит их ЦЕЛИКОМ, оставляя хвост пустым. Лечится абзацами-связками перед таблицей, а не правкой разрывов. Контроль пустых страниц делать по рендеру: длина `extract_text()` каждой страницы ≥ порога.
- У рисунков из matplotlib гасить белые поля: `bbox_inches="tight", pad_inches≈0.02` при генерации; в docx выставлять `a:ext` cx/cy пропорционально фактическому соотношению сторон PNG, иначе под подписью остаётся белёсый хвост.
- Слушай пользователя про объем: «распиши всё» = расширять разделы фактологией (история компании в регионе, даты, технологии) с поиском в интернете, сохраняя структуру разделов эталона.
