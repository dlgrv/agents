### Тулчейн для .asm на Mac (проверено сборкой и прогоном)
- **Трансляция решена и проверена на реальном коде бригады.** На GitHub есть юниксовый порт оригинального ассемблера Motorola **asm56000 v4.1.1** (искать «asm56000 unix port»): на macOS собирается чистым `make`, бинарник в `<repo>/asm56000c/asm56000`. `asm56000 -A -B./out.lod in.asm` на адаптированном листинге даёт «0 Errors / 0 Warnings» — скрин трансляции годится в отчёт как Рис. 1 (шаг «трансляция» по Дедову закрыт). Нюансы вызова: (1) ассемблер сам дописывает `.asm` к имени исходника — если имя файла не ровно `<то, что передано>.asm`, получишь «Cannot open source file» (лечится `cp` под нужное имя); (2) `-B` писать слитно с путём (`-B./out.lod`) — раздельное `-B out.lod` проходит молча, но .lod не появляется; (3) комментарии в .asm — только латиницей: кириллица ломает трансляцию, держать копию `*_lat.asm` с латинскими комментариями (русские — в тексте отчёта). Выходной .lod у порта **бинарный**, не классический текстовый Motorola (`_DATA P ...`) — не пытаться читать его как текст. Скрин терминала для отчёта: вызов и вывод в лог-файл → PIL-рендер моноширинным шрифтом (Menlo) на тёмном фоне в PNG.
- **Исполнение — эмулятор dsp56300** (github dsp56300/dsp56300, C++/cmake): собираются `build/source/dsp56kEmu/libdsp56kEmu.a`, `libdsp56kBase.a`, `asmjit`. Встроенный ассемблер **построчный**: `dsp56k::Assembler::assemble(text)` транслирует ОДНУ инструкцию (`AssembleResult.word[2]`) — для полного .asm нужен свой двухпроходный лоадер (метки, `equ`, `org`, `dsm`, параллельные пересылки `X:(R0),X0 Y:(R4),Y0`, `DC` с дробными). Лоадер написан и работает (см. ниже).
- **Сборка и запуск раннера (проверено реальным прогоном)**:
  - Раннер собирать с тем же флагом, что и библиотеки: `c++ -std=c++17 -DDSP56K_FORCE_INTERPRETER=1 -I source/dsp56kEmu -I source -I source/dsp56kBase -I source/asmjit/src runasm.cpp <три .a> -o runasm`. Несовпадение флага между библиотекой и раннером = segfault на первом `dsp.exec()`.
  - Периферия: пара `(Peripherals56362, Peripherals56362)` НЕ поддерживается и даёт null → segfault; рабочая конфигурация X=`Peripherals56362`, Y=`PeripheralsNop`.
  - **MOVEP-порты в 56300 не читают Y-память**: `MOVEP Y:$FFE1,Y1` у эмулятора уходит в периферийное пространство $FFFF80+ (см. `op_Movep_ppea` / `memReadPeriphFFFF80` в `dsp_ops_move.inl`) и возвращает 0, а не содержимое ячейки. Для программ уровня симулятора 56000, где «порты» — обычные ячейки Y-памяти, заменять MOVEP в загружаемой программе на обычный `MOVE Y:<$ffe1,Y1` / `MOVE A,Y:<$ffe0`; опкоды для подстановки получать встроенным ассемблером (`assemble("move y:<$ffe1,y1")`), а не считать руками.
  - Трассировка — `dsp.regs().a/m[0]/r[0]`, `dsp.getPC()`; запись отсчёта — `memory.set(MemArea_Y, 0xFFE1, ...)` перед `dsp.exec()`. Корректность прогона проверять по инициализации: `MOVE #2599,M0` даёт m−1 (модуль кольца), обнуление буфера через REP инкрементирует R0.
  - Статус: инициализация программы выполняется пошагово верно; для полного прогона фильтра осталось сделать замену MOVEP→MOVE в лоадере — после неё трассировка выдаст отсчёты ИХ (n=0 → g0; n=m → g1·b0) для скрина в отчёт.

## Чтение учебника-PDF
Сканированный учебник читается постранично: `pypdfium2` (есть в системном python3) — `pdfium.PdfDocument(path)[i].render(scale=2.0).to_pil().save('/tmp/pN.png')`, затем vision_analyze по каждому PNG. Границы лабы определять по соседним заголовкам ЛР (следующая за нужной лаба = конец диапазона).

**`extract_text()` у PDF этого практикума не работает даже не на сканах** — у PART1/PART2 шрифты со сломанной CID-картой (текст извлекается как `/G46/G11/...`). Учебник «ЦОС ч.2» тоже почти не даёт текста. Сразу рендерить страницы в PNG, не тратить попытки на текстовое извлечение.

**Старые русские .txt (СОСТАВ.TXT и т.п.) — в cp1251**: `cat` даёт кракозябры; читать `iconv -f cp1251 -t utf-8`.

## ЛР3 «Гребенчатый фильтр» (учебник ч.2, стр. 55–59) — фактология
- Уравнения: `y(n) = g0·x(n) + g1·f(n−m)`, `f(n) = b0·x(n) − a1·f(n−m)`. Пять параметров: g0 — прямой сигнал, g1 — громкость эха, b0 — вход в линию задержки, a1 — затухание эха, m — задержка (в отсчётах).
- Устойчивость: |a1| < 1. Период «гребёнки» АЧХ: fд/m. Время затухания эха до 1%: ln(0.01)/ln|a1| отражений.
- Вариант по номеру бригады (табл. 1). Бригада 1: b0=0.21, a1=−0.69, m=2600, g0=0.30, g1=0.68; fд = 8 кГц → задержка 325 мс.
- Артефакт: ассемблерный листинг EX_3_1 из методички — адаптируется заменой 5 констант (`equ`).
- ТЗ: (1) ассемблерная реализация под DSP5600x, (2) характеристики на программной модели, (3) речевой сигнал на плате EVM56K — платы нет, пункт заменить прогоном WAV «до/после» через модель.

## Раздел отчёта «Архитектура DSP5600x» и защита (заметки Дедова)
Дедов требует в отчёте раздел про процессор со структурной схемой и спрашивает систему команд на защите:
- **5 особенностей архитектуры**, каждую объяснить «зачем для ЦОС» и привязать к строкам листинга EX_N_M: (1) модифицированная гарвардская архитектура — три раздельные памяти X/Y/P, команда и два операнда читаются одновременно (`ORG X:`, `ORG Y:`, `ORG P:$100`, порты в Y:$FFE0); (2) моношинная организация — данных шина одна, параллелизм выжимается параллельными пересылками `X:(R0),X0 Y:(R4),Y0` за такт; (3) MAC-устройство — умножение с накоплением за такт, сердце КИХ/гребенчатого фильтра (`MPY`, `MAC`, `MACR`); (4) два аккумулятора A и B — параллельные вычисления; (5) аппаратная поддержка циклов — `REP #N` крутит команду N раз без проверок-переходов, N тактов вместо 3–5 на виток программного цикла.
- **Схему процессора рисовать самому** (X/Y/P-памяти, шина, ALU+MAC, A/B, AGU с R0–R7/M0) и подписывать по ГОСТ «Рисунок N — Структура процессора DSP5600x». НЕ искать «рис. 16» в методичках: рисунки «ЦОС ч.2» вообще без номеров (структуры оформлены текстовыми заголовками «Структура алгоритма»), в PART1 такой схемы тоже нет — нумерация «рис. N» у Дедова с его лекций, проверено рендером всех страниц.
- **Система команд к защите**: в `MOVE` сначала ОТКУДА, потом КУДА (`MOVE X:(R0),Y0` — из памяти в регистр Y0; не путать порядок). Четыре класса: сложение `ADD X0,A`, вычитание `SUB X0,A`, умножение `MPY X0,Y0,A`, умножение с накоплением `MAC X0,Y0,A` (с округлением — `MACR`). В отчёте хорошо работает таблица «команда → что делает → где в нашем листинге».
- **Порядок выполнения лабы по Дедову**: (1) написать .asm текстом, (2) трансляция `Asm56k.exe` → `.cld`, (3) отладка в симуляторе. Без СКР пп. 2–3 недоступны — в отчёте честно указать, что среда недоступна и отладка заменена программной моделью, результаты сверены с теорией числом.

**Верификация модели — числом, не глазом:** пики ИХ обязаны стоять на n = k·m с амплитудами g0, затем g1·b0·(−a1)^k. Сверить вычисленные значения с формулой до ~5 знаков — тогда графики годны в отчёт без визуальной проверки каждой картинки (анализ изображений может быть недоступен, числовая сверка работает всегда).
