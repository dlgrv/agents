# РГР по ЦОС (Дедов А.Н.) — устройство задания и материалы курса

Курсовая/РГР «Проектирование системы ЦОС» / «Использование специализированных микропроцессоров». Главная часть РГР — схема электрическая функциональная (Э2); на «тройку» на защите достаточно доказать, что схема соответствует заданию.

## Шифр варианта
7–8 полей через запятую, порядок как в «Задание_РГР_таблица.doc»:
1. Тип процессора: М = Motorola/NXP, А = Analog Devices;
2. Частотный диапазон: 1 = 100–10000 Гц, 2 = 20–20000 Гц, 3 = 300–3400 Гц;
3. Точность: 1 = 0,5%, 2 = 0,1%, 3 = 0,05%, 4 = 0,01%;
4. Число входных каналов: 1/2/4/8;
5. Число процессоров: 1/2/4;
6. Внешняя память: 0 = нет, 1 = да;
7. Последовательный канал: 0 = USB, 1 = SPI, 2 = I2C, 3 = RS-232C, 4 = RS-485;
8. № программы (1–18): БПФ 256/512/1024, Хартли 256/512, эквалайзер, передискретизатор, эхокомпенсация, децимация, ревербератор, ФНЧ/ПФ с БИХ или КИХ и т.д.

Для фильтров: f1 = Fmax/2, f2 = 1.1·f1, f3 = f1 + Fmax/3, f4 = 1.05·f3 (Fmax — верхняя частота спектра входного сигнала).

⚠️ В файле таблицы вариантов привязки шифров к фамилиям НЕТ — свой номер узнавать у преподавателя/старосты, не пытаться вычислить из документа.

## Состав работы (по методуказаниям)
Пояснительная записка 30–45 стр.: титульник → аннотация (рус + англ; в конце справочные данные: число страниц/таблиц/рисунков/источников) → ТЗ → содержание → введение (1–2 стр., обзор ПЦОС NXP/TI/Analog Devices) → 4–5 глав: анализ ТЗ; разработка структурной схемы; выбор процессора ЦОС и компонентов; разработка функциональной схемы и алгоритма; разработка ПО → заключение → литература → приложения (текст программы, схема Э2, справочные материалы). Работа с отступлениями от ЕСКД (ГОСТ 2.105-95) до защиты не допускается.

## Схема Э2
- Рисовать в **КОМПАС-3D** — так сделан пример одногруппников; у группы есть .cdw-заготовки в Downloads. Методуказания программу не навязывают, но УГО должны быть по ГОСТ (sPlan и т.п. — не ГОСТовские, риск отказа).
- Лист горизонтальный ~А3/А2, основная надпись (штамп) со шрифтом вида `КНФУ.XXXXX.00N Э2` и названием «Использование специализированных микропроцессоров. Схема электрическая функциональная».
- Пример (Ягодарова и соавт., записка 61 стр., ИТС-41з): 5 микросхем DD1–DD5 — DSP56658 (процессор ЦОС), АЦП AD7468, ЦАП AD7303, память AS7C31026 (ОЗУ) + W49L102 (ПЗУ), хост AT89C5131A-L (8051, SPI-канал), клавиатура 4×4, дисплей WH-1602B1; программа — ПФ с КИХ. Если шифр варианта совпадает по процессору и каналу — схему переиспользовать с правкой под свой вариант.

## Буквенные коды и частоты (вопросы защиты по схеме)
- Коды по ГОСТ 2.710: DD — цифровая микросхема, DA — аналоговая (на входе — усилитель/согласователь между разъёмом и АЦП), C — конденсатор, R — резистор, ZQ — кварцевый резонатор, SB — соединитель (разъём). Цифра — порядковый номер экземпляра.
- Частота кварца кодека (по методуказаниям): 16,384 МГц (= 2¹⁴ — степень двойки, чтобы делением нацело получать частоты дискретизации 8/16/32/64 кГц: F_SCLK = 16,384/8 = 2,048 МГц, F_S = 16,384/2048 = 8 кГц по умолчанию). Для кварца процессора DSP5600x конкретного числа в методичке нет — на защите отвечать «ряд, кратный частоте отсчётов, напр. 12,288 МГц = 1536 × 8 кГц».
- Уровни ГОСТ-схем Э (вид «Э» — электрическая; бывают ещё Г, П, К, Оп): **Э1** структурная («из чего состоит», укрупнённые блоки) → **Э2** функциональная («что каждая часть делает», функциональные части и процессы) → **Э3** принципиальная («как это спаять», все элементы с номиналами и выводами) → **Э4** соединений/монтажная (физические проводники, жгуты, платы) → **Э5** подключений (внешние подключения: что воткнуть снаружи) → **Э6** общая (изделие + все внешние устройства, система целиком). На защите спрашивают «чем Э2 отличается от Э3» и «почему у вас Э2, а не Э3» — готовый ответ: «по заданию требуется функциональное деление системы и процесс преобразования сигнала (кодек → процессор → контроллер); Э3 с номиналами и цоколёвкой всех выводов избыточна для этапа функционального проектирования».
- Графа «Масштаб» в штампе схемы не заполняется (УГО без соблюдения размеров).

## Фактура схемы пользователя (вариант: сжатие аудио)
Тракт: SB1 (входной разъём) → DA1 кодек CS4218 (16-битный стерео, входы LIN1/RIN1 через R1/R2/C1, кварц ZQ1 16,384 МГц) → по последовательному аудиоинтерфейсу (SDIN/SCLK/SSYNC) → DD1 процессор DSP56858 (ESSI0, программа сжатия) → по хост-порту HI08 (шина HD0–HD7/D0–D7, адрес HA0–HA2, сигналы HCS/HRW/HREQ, через DMA) → DD2 хост-контроллер MC68HC11K4 → UART (TXD/RXD) → DD3 конвертер CH340 → USB (D+/D−) → компьютер. Обратный путь — зеркально: декодер в DD1 → SD0UT → ЦАП кодека → сглаживающий фильтр → LOUT/ROUT.
Алгоритм сжатия по записке: матрицирование стерео (L+R, L−R) → блок фильтров на МДКП → психоакустическая модель (порог маскирования) → динамическое распределение бит → масштабирующий множитель; сжатие 10–12×.

## Доказательства соответствия ТЗ (главные вопросы защиты)
- **Частотный диапазон 100–10000 Гц**: доказывать цепочкой «кодек 16 бит + fд 48 кГц → полоса до 24 кГц покрывает 10 кГц с запасом; 94 дБ динамического диапазона ≥ точности варианта» — с числами, не словами.
- **2 входных канала**: каналы разделены временным мультиплексированием (TDM): в кадре ESSI первый слот — левый, второй — правый; начало кадра отмечает SSYNC, биты задают SCLK; процессор по прерыванию «кадр готов» раскладывает слова в два массива памяти и обрабатывает за один проход. Матрицирование L+R/L−R — часть алгоритма сжатия (разностная тише → кодируется грубее).
- **1 процессор ЦОС, без внешней памяти**: весь тракт обработки — внутри DD1 (внутреннее ОЗУ программы/данных); DD2 — не ЦОС (8-разрядный, без MAC), его роль — управление и связь; DD3 — только конвертер интерфейса.
- **Реализация USB**: на схеме нет отдельного USB-контроллера у процессора — последовательный канал собран цепочкой UART (DD2) → конвертер CH340 (DD3) → дифференциальная пара D+/D−.

Готовая шпора по схеме с этими доказательствами: `university/Цифровая обработка сигналов (Дедов А.Н.)/Шпаргалки/Шпаргалка_Э2_схема.pdf` (генератор-скрипт в /tmp — правки только перегенерацией).

## Хост-процессор и USB (вопросы защиты)
- **Роль хост-контроллера** (DD2 MC68HC11K4, 8-разрядный, SPI+UART, шина немультиплексированная — потому и выбран: совпадает с HI08 «без дополнительной логики»): (1) связь с компьютером — канал USB из ТЗ идёт только через него; (2) клавиатура SB2…SB17 (порт A, программный опрос матрицы 4×4) и LCD HG1 (SPI, порт D: SCE/SDIN/SCLK); (3) начальная загрузка DSP — внешней памяти по ТЗ нет, поэтому хост после включения побайтно грузит программу во внутреннюю память DSP через хост-порт (источник — хост, не ППЗУ). Формулировка для объяснения: DSP — «повар» (только счёт), хост — «официант» (связь, кнопки, включение повара на смену); хост master, DSP slave.
- **Сигналы HI08** (режим D по HPCR: HCSEN=1, HDDS=0 — один строб, HMUX=0 — немультиплексированный): данные HD0–HD7↔D0–D7 (параллельный байт); адрес HA0–HA2↔A0–A2 (выбор внутреннего регистра HI08: 3 линии = 8 адресов); HCS (выбор кристалла, активный 0 — без него порт игнорирует всё); HRW (направление чтение/запись); HDS (строб «данные действительны сейчас»); HREQ (DSP→хост «готов/нужен обмен») + HACK (хост→DSP подтверждение) — рукопожатие, чтобы данные не терялись. Дальше данные уносит DMA — ядро DSP не отвлекается.
- **USB по ТЗ** (в канале 0): у MC68HC11K4 своего USB нет → UART (TXD/RXD) → конвертер CH340 (DD3) → D+/D−. Сигналы кабеля: D+/D− (дифпара: бит = какая линия выше; помеха действует на оба провода одинаково и вычитается), VBUS +5 В, GND. Кодирование NRZI: «0» — перепад, «1» — без перепада; bit stuffing (принудительный 0 после 6 единиц) держит синхронизацию; подтяжка 1,5 кОм на D+ = флаг Full Speed 12 Мбит/с; SE0 (обе линии 0) = EOP/отключение. Пакет: SYNC → PID → ADDR+ENDPOINT → DATA (0–1023 байта) → CRC → EOP; опрашивает всегда хост-контроллер КОМПЬЮТЕРА, наше устройство ведомо и говорит только когда спросят. Фраза для защиты: «наша система не формирует USB-сигналы сама — в этом смысл конвертера».
- **Диаграммы к защите** сгенерированы matplotlib'ом и лежат в `Шпаргалки/`: `diag_uart.png` (кадр UART 8N1: idle → старт(0) → 8 бит LSB-first → стоп(1); бит при 115200 бод ≈ 8,7 мкс — это «наша» диаграмма, связь DD2↔DD3), `diag_usb_nrzi.png` (три дорожки CLK/D+/D−, видно перепады на «0»), `diag_usb_packet.png` (структура пакета цветными полями). Временные диаграммы интерфейсов строить из инвариантов (D− ≡ инверсия D+; бит 0 = перепад относительно предыдущего состояния) — тогда корректность картинки доказуема численной проверкой инвариантов, без просмотра изображения.
