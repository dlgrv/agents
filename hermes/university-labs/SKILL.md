# Университетские лабораторные работы

Контекст: Moodle-курсы универа (напр. «Нейронные сети», преподаватель Иванов К.О.), студент Долгирев Л.М., группа ИТС-41з. Лабы лежат в `~/university/<Курс>/<ЛРN>/`.

## Порядок работы

1. Прочитать методичку целиком до начала — там все задания, контрольные вопросы и требования к отчёту. Ссылка в Moodle может вести на Google Drive, а файл оказаться не PDF, а JSON ноутбука Colab: после скачивания проверять `file` — если контент начинается с `{"cells":`, парсить `json.load` и собирать текст из `source` ячеек (markdown = задания и вопросы, code = скелет решения). Скачивание Drive-файла: `curl -sc /tmp/gc 'https://drive.google.com/uc?export=download&id=ID'` → вытащить `confirm`/`uuid` из формы → повторный curl с ними (без этого приходит страница проверки или обрезанный файл).
2. Скрипты: по одному на задание, номер задания в имени файла, имена .py — **латиницей** (`task1-create-db.py`), не кириллицей. Каждый скрипт запустить и проверить вывод до сдачи.
3. Отчёт — docx по ГОСТ: Times New Roman 14, полуторный интервал, отступ первой строки 1,25 см, поля 30/10/20/20 мм. Имя файла `ЛРN_Долгирев_ИТС-41з.docx`.
4. Сдача: формат вложений в задании/методичке часто вообще не указан — по умолчанию один docx-отчёт; когда сдаётся комплект (отчёт + ноутбук + данные), прикреплять каждый файл отдельно — Moodle принимает до 20 файлов по 128Мб, zip не обязателен. Наполнение комплекта согласовать с юзером (docx / ipynb / данные) перед загрузкой. Загрузка файлов в Moodle — прикреплять к ответу на задание внутри курса.
5. Упаковка: все файлы лабы в одну папку `ЛРN_Долгирев_ИТС-41з/`, рядом zip с тем же именем.
6. Если сдаёшь .ipynb вместе с docx: в ноутбуке только код и краткие пометки — markdown-ячейки не должны дублировать текст отчёта (преподаватель читает отчёт, дубль в ноутбуке = расхождение версий). Текст markdown-ячеек тоже прогнать по чек-листу ИИ-паттернов.

## Вход в Moodle
`elearning.volgatech.net` редиректит на `auth.volgatech.net` (Trusted.ID): логин вписать самому, пароль — только через browser_vault_fill, затем нажать кнопку «ВОЙТИ» (искать по тексту кнопки, у неё нет type=submit). После входа: страница курса → задание → блок «Материалы» содержит ссылки на методичку.

## Правила отчёта docx

- В docx — **только ответы на контрольные вопросы**: шапка (название лабы, «Выполнил», «Проверил») + вопросы с ответами. Без цели, схемы БД, хода работы с кодом, вывода — код и выводы живут в .py-файлах. Расширять отчёт разделами только по явной просьбе.
- Упоминания имён .py-файлов внутри docx держать синхронными с реальными именами: переименовал файл — замени упоминания в docx (замена по runs через python-docx).

## Питфоллы

- **Загрузка файлов в Moodle через браузер: на странице ответа нет `input[type=file]`** — открывать пикер кликом по `.fp-btn-add` в тулбаре filemanager, в пикере выбрать репо «Загрузить файл» (появится `input[name=repo_upload_file]`), файл вписывать через CDP (`DOM.getDocument` → `DOM.querySelector('input[type=file]')` → `DOM.setFileInputFiles`), подтвердить «Загрузить этот файл» — и повторять на каждый файл.
- **У большинства заданий нет кнопки «Отправить на проверку»** — после «Сохранить» статус «Ответы для оценки» и есть сдано (так настроил преподаватель); не тратить время на поиск кнопки отправки, проверять статус и список файлов в «Ответ в виде файла».
- **zip пересобирать последним, после всех правок файлов** — архив не обновляется сам, устаревший zip незаметно уедет в сдачу.
- python-docx недоступен в execute_code-sandbox — работать с docx через `terminal` системным `python3`.
- Русские имена файлов в zip: `unzip -l` показывает кракозябры — это норма листинга, не порча архива; проверять состав по количеству файлов.
- **Перед сдачей прогнать итоговый текст docx по чек-листу ИИ-паттернов** (файл `стиль-без-ии-паттернов.md` в университете): маркерные фразы, повторы одного союза в соседних предложениях («Кроме того, …» дважды подряд) и т.п. Проверять именно собранный текст отчёта, а не исходные материалы.
