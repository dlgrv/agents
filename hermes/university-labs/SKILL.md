# Университетские лабораторные работы

Контекст: Moodle-курсы универа (напр. «Нейронные сети», преподаватель Иванов К.О.), студент Долгирев Л.М., группа ИТС-41з. Лабы лежат в `~/university/<Курс>/<ЛРN>/`.

## Порядок работы

1. Прочитать методичку (PDF) целиком до начала — там все задания, контрольные вопросы и требования к отчёту.
2. Скрипты: по одному на задание, номер задания в имени файла, имена .py — **латиницей** (`task1-create-db.py`), не кириллицей. Каждый скрипт запустить и проверить вывод до сдачи.
3. Отчёт — docx по ГОСТ: Times New Roman 14, полуторный интервал, отступ первой строки 1,25 см, поля 30/10/20/20 мм. Имя файла `ЛРN_Долгирев_ИТС-41з.docx`.
4. Сдача: код-файлы + отдельный файл с ответами (уточнить у преподавателя, если формат неясен). Загрузка файлов в Moodle — прикреплять к ответу на задание внутри курса.
5. Упаковка: все файлы лабы в одну папку `ЛРN_Долгирев_ИТС-41з/`, рядом zip с тем же именем.

## Правила отчёта docx

- В docx — **только ответы на контрольные вопросы**: шапка (название лабы, «Выполнил», «Проверил») + вопросы с ответами. Без цели, схемы БД, хода работы с кодом, вывода — код и выводы живут в .py-файлах. Расширять отчёт разделами только по явной просьбе.
- Упоминания имён .py-файлов внутри docx держать синхронными с реальными именами: переименовал файл — замени упоминания в docx (замена по runs через python-docx).

## Питфоллы

- **zip пересобирать последним, после всех правок файлов** — архив не обновляется сам, устаревший zip незаметно уедет в сдачу.
- python-docx недоступен в execute_code-sandbox — работать с docx через `terminal` системным `python3`.
- Русские имена файлов в zip: `unzip -l` показывает кракозябры — это норма листинга, не порча архива; проверять состав по количеству файлов.
