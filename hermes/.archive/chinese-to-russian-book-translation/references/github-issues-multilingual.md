# GitHub Issues for Multi-Language Projects

## Issue Creation Strategy

- **Write in the primary project language** unless explicitly requested otherwise
- **Include links to multilingual resources** if relevant (forks, translations, sites)
- **Mention existing issues** that share context (e.g., "continuing from #14")
- **Reference user pain points** from closed issues to show continuity

## Localization Tips

- **Issue titles should be clear in both original and target languages** if possible
- **Body can mix languages** when addressing international audiences
- **Always include full URLs** to multilingual sites/resources
- **Tag appropriately** if your project supports language-specific labels

## Example Structure for Translation Updates

```markdown
@original_author 你好，接着 #14 / #4 的翻译工作汇报一下进展。

...description of progress...

- 🇨🇳 Resource: [link]
- 🇬🇧 Resource: [link] 
- 🇷🇺 Resource: [link]

...details...

如果觉得有用，欢迎把链接放进 README；想改哪里直接说。
```

## Linking to External Resources

- **Always provide full, clickable URLs** — no shortened links
- **Root-level links** should auto-detect language when possible
- **Language-specific links** should clearly indicate the language
- **Mention README placement** if requesting updates

## Pitfalls

- **Don't hijack existing issues** with unrelated updates — create new issues for new topics
- **Don't assume** the original author speaks your language — include context in both directions
- **Don't omit** the original issue reference if continuing a conversation
- **Don't use machine translation** for user-facing content without review
